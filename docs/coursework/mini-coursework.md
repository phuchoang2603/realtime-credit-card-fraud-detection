## Documentation requirements

The repository README supplies business scope, navigation and a folder map; the architecture guide supplies planned deployable-unit diagrams with numbered data-bearing arrows. Each implementation must add file/module descriptions and function/class documentation. Put detailed schema, optimization and proof documents under `docs/`, with screenshots embedded next to an explanation of what each proves. A folder of unexplained images is insufficient.

The existing [Dockerfile](../../infra/docker/fraud-service.Dockerfile) is a packaging starting point. It does not prove measured size improvement or a complete local multi-service environment. Existing fraud-service code and historical research do not prove the new generators, DP1-DP3, or coursework acceptance.

Continue with the [final ML extension](final-ml.md) only while preserving the accepted baseline and its comparisons. Named course tools are examples; document equivalent capabilities and proof when choosing replacements.
