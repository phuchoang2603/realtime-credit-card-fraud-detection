## Why

Strict streaming requires every live payment event to be produced by Payments, not fabricated by a simulator. That needs the smallest gateway that can take a checkout snapshot, run an attempt through the fraud decision and a processor, and durably record the lifecycle. The marketplace (`refurbished-marketplace`) becomes the gateway's first real integration and replaces its own payment service and hosted-payment simulator, so the slice also needs a hosted checkout page and signed outcome webhooks. Kafka publication of the ledger lands here too, because the notifier consumes it; the live simulator and fault injector (`simulate-live-traffic-with-transport-faults`) and Flink stay out, and the marketplace side lands in its own `integrate-payment-gateway-checkout` change.

## What Changes

- **Integrations as configuration at Edge**: integration ID, API key hash, synthetic flag and optional webhook URL, signing secret and subscribed event types come from External Secrets. There is no Accounts service. Merchant and customer IDs are UUIDv5 values of the integration and external seller or buyer ID, computed in Payments; merchant and customer facts travel in each payment's snapshot, so there is no provisioning call.
- Add a Go **Payments** service whose authoritative state is versioned payment and attempt rows in Postgres, with an append-only `payment_events` ledger written in the same transaction. It handles idempotent payment creation, checkout sessions with scoped checkout tokens and idempotent attempts. Attempts call `fraud.v1` Decide (failing closed when fraud is unavailable), persist a processor effect intent before calling the processor and treat timeouts as unknown, within a 5 s attempt budget. Recovery and expiry workers resolve unknown outcomes and close open payments. Ledger rows are never updated or deleted; the runtime role can only insert and read them. This is not event sourcing: state is not rehydrated from the ledger.
- **Idempotency keys everywhere**: every mutating call carries `Idempotency-Key`. Payments claims each key in Redis (set-if-absent with a request digest and in-flight marker) and completes it with the result; the Postgres unique key committed with the first ledger event stays the final arbiter, so a Redis miss or loss falls back to Postgres and never fails open.
- **Redis via the platform's Redis operator**: one standalone `Redis` resource (Valkey), bounded memory with `noeviction`, TTL-based records and Payments-only access. No sidecar or chart-managed image.
- Add a Go **processor simulator** with its own store: idempotent sale by operation key, outcomes set by the vault fixture's behavior, seeded latency and timeout injection, and an operation status query.
- Add an isolated Go **vault simulator** with its own database. Edge is its only tokenizing caller: it maps allow-listed test card numbers to fictional cards and behaviors and returns opaque integration-scoped tokens. Only the processor identity may resolve processing fixtures. This demonstrates a PCI DSS-oriented boundary without accepting real card data or claiming compliance.
- **Publish the ledger to Kafka**: a Debezium outbox connector on a repository-owned Strimzi Kafka Connect publishes each committed event's stored `PaymentEvent` bytes to `payments.events.v1`, keyed by payment, in commit order. Payments has no Kafka code. The topic is internal to the gateway.
- Add a Go **notifier**: it consumes `payments.events.v1`, records one delivery per subscribed event keyed by `event_id`, and POSTs signed JSON (`Gateway-Signature`, `Idempotency-Key: <event_id>`) with backoff and jitter. Integrations depend only on this HTTP contract and the status query, not on the gateway's broker or schema.
- Add **checkout API** routes to Edge: payment creation with the full snapshot, payment status, attempt submission, and a synthetic-only `POST /v1/payment-methods` that tokenizes an allow-listed test card for the live simulator. Add a **hosted checkout page** at `/checkout/{session_id}`, the only publicly routed path; a declined attempt can be retried there until the payment expires. Edge computes address and IP-network fingerprints, so street lines and raw IPs never reach internal services. Synthetic integrations use a non-secret fingerprint key shared with the historical generator and may send simulated client context.
- Keep provider wire protocols behind the Payments adapter boundary. The first slice uses `processor.v1` gRPC and synthetic tokens; ISO 8583 and real acquirer profiles are later directions.
- Add gRPC contracts `payments.v1` PaymentService, `vault.v1` and `processor.v1`, generated once in the shared Go module.
- Deploy Edge, Payments, notifier, vault simulator, processor simulator, Redis and Kafka with a CloudNativePG cluster owned by this repository, per-service databases and roles, one public Gateway API HTTPRoute for `/checkout/*`, authenticated service calls and network policy.
- The CI Go job lints and tests every Go module, and release adds one image job per new service plus the Connect image.
- Document functional/non-functional requirements and later merchant-based database sharding. Remove automated reconciliation and settlement-file ingestion from project scope; retain operation-status recovery.

## Capabilities

### New Capabilities

- `payment-processing`: Payments commands, versioned state with an append-only ledger, Redis-first idempotency backed by Postgres, fraud and processor orchestration, unknown-outcome recovery, expiry and signed outcome webhooks.
- `processor-simulator`: Simulated external processor with idempotent sale, deterministic fixture behaviors, fault injection and status queries.
- `payment-event-publication`: Ordered, at-least-once publication of committed ledger events to the internal `payments.events.v1` topic.
- `checkout-api`: Edge HTTP routes, configured integrations, hosted checkout page, test-card tokenization, fingerprinting, client context, isolated synthetic vault access and error mapping.

### Modified Capabilities

- `payment-contracts`: Reworks the envelope (no `causation_id`), snapshot (no merchant category), labels and package layout, and adds representative contract JSON fixtures.
- `fraud-decision`: Moves the decision RPC to `fraud.v1` returning the shared `RiskAssessment`.
- `service-conventions`: Adds health, lifecycle and persistence expectations for internal Go gRPC services.
- `focused-verification`: Adds Go service tests (table-driven state machine tests, idempotency, recovery, ledger append-only, webhook delivery and store integration) to CI.
- `talos-gitops-deployment`: Adds gateway workloads, the database cluster, the Redis resource, Kafka with Connect and the outbox connector, the hosted checkout HTTPRoute, and one image job per service.

## Impact

- New Go modules `src/payments`, `src/notifier`, `src/vault-simulator`, `src/processor-simulator`; edge gains `internal/transport`/`application` packages for checkout routes, the hosted page, integration config and gRPC clients.
- Contracts: `contracts/payments/v1/{types,events,labels,payments}.proto`, `contracts/fraud/v1`, `contracts/vault/v1`, `contracts/processor/v1`; `contracts/fraud/v2` and `contracts/labels/v1` are removed; the existing `contracts/synthetic/identity-vectors.json` gains test-card method fingerprint cases. `codegen:proto` generates Go bindings once in `shared/proto`; one shared module also groups reusable test/runtime/security helpers. **Contracts are reworked from scratch, without compatibility**: `payments.v1` holds shared types, one `RiskAssessment`, lifecycle events (no `causation_id`, no merchant category, fresh field numbers), fraud labels and `PaymentService`; `fraud/v2` becomes `fraud/v1` returning `RiskAssessment`; `labels/v1` is folded into `payments.v1`; the fraud service is ported minimally since it will be rewritten.
- One `payment-gateway` application chart for all five Go services, the database cluster and the `Redis` resource; `infra/charts/kafka` copied from refurbished-marketplace and `infra/docker/connect-debezium.Dockerfile`; one gateway child plus the separate Kafka child for the configured prod root; ExternalSecrets for integration keys, webhook secrets, fingerprint and token encryption keys, Redis password and CDC credentials. The retired dev root is not restored.
- Platform prerequisites already owned by talos-proxmox: CNPG operator, Strimzi operator, Redis operator, External Secrets and Istio Gateway API ingress behind Cloudflare Tunnel. No new platform component.
- CI Go job gains `go test` for all modules with shared testcontainers-go Postgres, Redis and Kafka helpers locally and in CI; `release.yml` gains five image jobs (payments, notifier, vault-simulator, processor-simulator, connect-debezium).
- Docs: architecture current foundation (no Accounts service; notifier added), payment flows (fail closed, synthetic context, state-plus-ledger authority, Redis-first idempotency), requirements FR-03/FR-08 (browser tokenization, webhooks and Kafka publication in the first slice) and NFR-01/NFR-08, gitops runtime table and local run instructions, the gateway implementation roadmap.
- Depends on `define-payment-and-decision-contracts`; owns the representative protobuf-JSON histories under `contracts/payments/v1/testdata/`. The marketplace's `integrate-payment-gateway-checkout` change depends on this change.
